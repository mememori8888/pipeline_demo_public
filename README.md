## 3. これまでの重要デバッグ ＆ 修正履歴

開発プロセスにおいて発生した技術的障壁と、それを解決した設計規約の変更記録。

### ① SQLiteにおける辞書型（dict）バインドエラー（InterfaceError）の解決
- **原因**: AIが自律自動生成したスキーマ（`generated_json_schema`）はPythonの `dict` 型オブジェクトであり、SQLiteの `TEXT` 型カラムにそのまま挿入しようとしたため型エラーが発生。
- **修正ルール**: データベース永続化のルールとして、**「構造化データ（JSON/Dict）をSQLiteに格納する際は、必ず `json.dumps()` を用いてテキスト文字列にシリアライズし、ロードする際は `json.loads()` でオブジェクトに復元する」**という規約を Repository 層に徹底した。

### ② 各ファイルにおける `json` モジュールのインポート漏れ（NameError）の根絶
- **原因**: 復元ロジックの追加に伴い、`crypto_repo.py`, `pii_masking.py`, `main.py` の内部で `json.dumps()` / `json.loads()` を使用した際、ファイルの最上部での `import json` 宣言が漏れていたためサーバーがクラッシュ。
- **修正ルール**: 該当するすべてのコアファイルの1行目に `import json` を完全追加。

### ③ デマスキング復元APIにおけるリクエスト項目名（タイポ）の統一
- **原因**: 解析API（`process`）が出力する項目名（`structured_data_masked`）と、復元API（`decrypt`）が型チェックで待ち受けていた項目名（`masked_json_data`）が食い違っていたため、FastAPIのバリデーション層（`422 Unprocessable Entity`）で通信が拒否されていた。
- **修正ルール**: Pydanticの `DecryptRequest` モデルを修正し、`masked_json_data` を必須の入力仕様として厳格に統一した。

### ④ テキストファイル（.txt）のバッチ解析スキャン対象への追加
- **原因**: 大量バッチ処理において、当初は安全策として画像とPDFのみを厳格にスキャン（フィルタリング）していたため、手元の `test.txt` がレーダーに捕捉されずスキップされていた。
- **修正ルール**: `scan_storage` ロジックを拡張し、`.txt` の拡張子を検知した際は MIMEタイプを `text/plain` として安全に Gemini File API へストリーム転送するよう最適化した。

## 4. 【大量書類専用】一括非同期バッチ解析エンジンの仕様

100枚〜1万枚規模の超大量ドキュメントが投入された際、APIサーバーを絶対に落とさず、かつアクセス制限（429エラー）を回避しながら並行稼働するエンタープライズ仕様の機能群。

### ① Background Tasks による「1秒受付」設計
- ユーザーが一括処理を要請した際、重いAI処理やファイル読み込みを同期的に待たせるのではなく、FastAPIの非同期バックグラウンドタスクへ即座に処理を委託。APIのレスポンスは**常に1秒以内（`"status": "accepted"`）**でパッと返り、フロントエンド画面を絶対にフリーズさせない。

### ② Gemini File API ＆ 429レートリミット自動迎撃
- 大容量のファイル転送に耐えるよう、ファイルをGoogleインフラへ一時アップロードする **Gemini File API (`client.files.upload`)** を全面採用。
- 短時間に大量のアクセスが発生してGoogle側から制限（429エラー）を食らった場合、自動的に検知して数秒ずつ待機時間を引き延ばしながら再挑戦する **「指数バックオフ付き自動リトライ（Exponential Backoff）」** を設置。
- 解析が成功した一時ファイルは `client.files.delete()` でGoogleサーバーから1秒で完全消去されるため安全。

### ③ 柔軟な枚数指定コントロール機能（`limit_count`）
- フォルダ内に1万枚の書類が山積みになっていても、API引数の `limit_count` に `1` や `5` などの数値を指定すれば、プログラムがその場で同期的かつ正確にファイルを自動カウントし、指定された枚数だけをきれいにスライス（切り出し）してエコにテスト実行できる。

### ④ 支配人プロンプト ＆ ファイル種別自動判定
- 標準で `ocr_markdown`（高精度OCR）、`contract_summary`（要約）、`image_risk_check`（視覚分析）に加え、どんな別物ファイルが混ざっていてもAIが空気を読んで自動仕分けする **`smart_classifier`** プリセットを完備。
- ユーザーが独自の指示を入力した場合は `custom_prompt`（自由記述）が最優先で採用される。
- メタ指示結合ロジックにより、どんなカスタム指示であっても、生成されるテキストファイルの1行目に必ず **`【ファイル種別判定】[写真 / 手書き書類 / デジタルPDF 等]`** の証跡ラベルを強制刻印して `output_txts/` フォルダへ自動保存する。

  * `channel_url`: 実在するYouTubeチャンネルのURL（例: `https://www.youtube.com/@Google`）

* **アウトプット:** 即時で受付完了ステータス。裏側で処理完了後、`output_txts/` へ大長編のトレンドニュースMarkdownファイルが自動出力されます。
